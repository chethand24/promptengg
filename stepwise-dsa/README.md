# StepWise Tutor – DSA Edition

React + Vite + TypeScript + Tailwind frontend, Express + TypeScript backend, and server-only Gemini and optional Anthropic integration. This is a standalone application; the existing parent Next.js project is preserved.

## Install and run

Requirements: Node.js 24+, npm. Docker Desktop with Linux containers is optional for code execution.

From PowerShell:

```powershell
cd "C:\Users\Admin\Documents\ChatGPT\prompt engg\stepwise-dsa"
npm install
Copy-Item .env.example .env
npm run dev
```

Open http://127.0.0.1:5173 (Vite prints another port if occupied). Both servers run together. Separate terminals may use `npm run dev:backend` and `npm run dev:frontend`. The API binds to loopback on port 3001. Vite proxies `/api` to it.

The three unchanged Python examples work immediately without a key. Choose **Two Sum**, **Binary Search**, or **Climbing Stairs**. In Guided Mode, submit a wrong answer to trigger a simpler prerequisite, then answer it and return to the original question. Hint 1 → Hint 2 → worked step unlock sequentially. The current question, rather than private future answers, is sent to the browser.

For custom problems, edit `.env`:

```dotenv
MOCK_LLM=true
LLM_PROVIDER=gemini
GEMINI_API_KEY=your-google-ai-studio-key
LLM_MODEL=gemini-3.5-flash-lite
```

Provider settings in `.env` reload on the next API request. Click **Check connection** after saving; this checks configuration presence, not credit balance or key validity. Restart the backend for other environment changes. Get a key from https://aistudio.google.com/apikey. Use a project on Google’s Free tier without paid billing enabled; free-tier quotas apply. The app cannot inspect or enforce the project’s billing tier. Google may use free-tier content to improve products. Gemini quota errors stop the pipeline; there is no paid fallback. One breakdown uses multiple requests, and repair attempts also count against quota. Keys are never used by Vite or sent to the browser. `LLM_MODEL` is read from the environment with no live-provider fallback. The demo setting applies only to the unchanged seed examples. All custom or edited code automatically uses the configured provider, even when `MOCK_LLM=true`. Set it to `false` to use the configured provider for the seeds as well. The setup banner reports whether the backend has a key and model configured; it does not verify the key with Anthropic. Mock grading uses keywords and is explicitly unverified.

## Build and production run

```powershell
npm run build
npm start
```

Open http://127.0.0.1:3001. Express serves the built frontend and API. Run these commands from the project root: runtime prompts are read from `backend/src/prompts/`. For distribution, retain that directory, `.env`, installed production dependencies, and `dist/`.

```powershell
npm test
npm run lint
npm run format
```

Tests cover schemas, ordered pipeline context, JSON repair, answer privacy, hints, remediation, disk persistence, low-confidence grading, disabled sandbox, timeout, and output caps. Tests use temporary session folders and mocked LLM output.

## Docker execution

```powershell
docker build -t stepwise-runner:local backend/sandbox
```

Set `SANDBOX_ENABLED=true` in `.env`, restart the backend, then open **Dry Run → Run in Docker**. No code is executed on the host if Docker/image is unavailable. The runtime never pulls images automatically.

Each test runs in a separate, non-root container: no network, no host mounts, read-only root filesystem, dropped capabilities, no-new-privileges, 256 MiB memory, 0.5 CPU, 48 processes, bounded temporary storage, 3-second execution timeout, and bounded output. Compilation gets up to 5 seconds; the host watchdog allows 10 seconds including startup and always removes the container. The program can access its disposable container filesystem and installed runtime; “no filesystem access” means **no host or persistent application files**, not literally no runtime files. C++ needs a disposable executable directory.

Java, C++, and JavaScript must be complete stdin/stdout programs (`Main` for Java). Python scripts work too; the three seed functions additionally have JSON stdin adapters: `{"nums":[2,7,11,15],"target":9}`, `{"nums":[1,3,5,7,9],"target":7}`, or `5`. Other function-only submissions need an entrypoint. The app does not invent a wrapper for arbitrary signatures. Comparison trims leading/trailing whitespace and otherwise requires exact stdout equality.

Python execution emits up to 100 line events with bounded primitive variable previews, displayed as an **observed runtime trace**. Values are captured before each line executes. Java/C++/JavaScript retain the clearly labeled predicted dry run. Introspection is best-effort: submitted code can disable or interfere with Python tracing, so it is diagnostic evidence, not a trusted proof. Test expectations are generated by the model and can themselves be wrong.

Docker integration cannot be validated on a machine without Docker. Do not expose this local demo as a public multi-tenant service without adding authentication, a dedicated sandbox worker/host, quotas, and stronger isolation.

## Architecture and persistence

```text
frontend/src/        React workspace, lazy Monaco, stream client, breakdown tabs
backend/src/        Express API, error handling, CORS, rate limit
  prompts/          Versioned stage, evaluation, remedial, hint, repair templates
  services/         Anthropic/mock adapter, pipeline, sessions, Docker runner
backend/sandbox/    Docker image and bounded multi-language process runner
shared/             Zod request/response contracts and seed examples
tests/              Vitest tests
docs/               Mermaid architecture and prompt design
```

Stage 0 understands the problem. Stage 1 builds a dynamic prerequisite DAG. Stage 2 calls the model separately for each subproblem with all previous results. Stage 3 synthesizes the analysis. Every model response is strict JSON parsed and validated by Zod; malformed JSON/schema output gets up to two repair calls. Invalid line ranges or dependency order are rejected. Progress streams as SSE events over POST fetch.

Guided sessions persist as atomic JSON files in `.sessions/` (override `SESSION_DIR`). UUID session IDs are local bearer identifiers. The backend retains private reference answers. A per-session lock and expected step ID reject concurrent/stale answers. Wrong or low-confidence answers insert at most two remedial branches per original question; remedial steps never recursively branch. Persisted trace records hints, misconceptions, completion, accuracy, and elapsed step time. `/metrics` summarizes sessions. Resume restores the last session after reload/restart. This storage/locking design targets one local backend process.

## API

| Endpoint                     | Contract                                                                                       |
| ---------------------------- | ---------------------------------------------------------------------------------------------- |
| `POST /api/analyze`          | `Input`; JSON or `Accept: text/event-stream` for progress/result/error events                  |
| `POST /api/guided/start`     | `Input`; returns only public session; also supports SSE                                        |
| `POST /api/guided/answer`    | `{sessionId, stepId, answer}` → feedback and public session                                    |
| `POST /api/guided/hint`      | `{sessionId, stepId}` → public session with next unlocked hint                                 |
| `POST /api/run`              | `{language, code, tests:[{name,input,expected}]}` → verified availability and per-test results |
| `GET /api/session/:id`       | Resume a public session, with input and source                                                 |
| `GET /api/session/:id/trace` | Persisted trace events                                                                         |
| `GET /api/metrics`           | Per-session and per-step metrics                                                               |
| `GET /api/health`            | Health and mock-mode flag                                                                      |

Input: `{problem,code,language,level,mode}`. Languages: `python`, `javascript`, `java`, `cpp`; levels: `Beginner`, `Intermediate`, `Advanced`; modes: `Full Breakdown`, `Guided Mode`. Code has a 300-line / 30,000-character limit and a lightweight code-vs-prose heuristic (not a parser). Request bodies are limited to 100 KiB. Requests are Zod validated; React escapes display text, no HTML rendering or eval is used. User strings are delimited and escaped in model prompts, with explicit prompt-injection instructions. CORS is configurable via `CORS_ORIGIN`; API calls are limited to 30/minute/IP. Local metrics are intentionally not an authenticated multi-user dashboard.

Markdown export includes the complete analysis. PDF export uses the browser print dialog with a full-breakdown print layout. The Monaco bundle is lazy-loaded and self-hosted; its worker bundle is intentionally larger than ordinary UI chunks.

See `docs/architecture.md`, `docs/prompt-design.md`, and `docs/verification.md` for details and verification limits.

## Provider configuration

`LLM_PROVIDER=gemini` is the default. `GEMINI_API_KEY` stays on the server. Responses use JSON mode and the same Zod validation and two-repair limit. To opt into Claude later, explicitly set `LLM_PROVIDER=claude`, `ANTHROPIC_API_KEY`, and a compatible `LLM_MODEL`. Existing guided sessions from a different provider must be restarted; they never silently send requests to the old provider. Configuration presence is not a key-validity or billing check. Gemini transport tests use mocked network responses; live inference awaits your key.

Temporary Gemini HTTP 502/503/504 responses receive at most two retries with exponential backoff (1s, 2s). Short Retry-After instructions are honored; long waits stop with a friendly message. Requests share a 90-second deadline. Quota/authentication failures and network timeouts are not automatically retried. No alternate provider is called.
